# 成员采集质量与文字可读性修复实施计划

## 目标

按照已批准设计，将成员采集清晰度默认门槛从 100.0 调整为 40.0，在模糊提示中显示实时分数，并显式修复登记向导和主界面的深色主题文字对比度。

## Task 1：建立失败测试

- 修改 `tests/unit/test_config.py`，期望示例配置的 `min_sharpness` 为 40.0。
- 修改 `tests/unit/test_core.py`，验证模糊提示同时包含实际清晰度与门槛。
- 扩展 `tests/ui/test_enrollment_wizard.py`，验证姿态、原因和进度条使用专用对象名。
- 扩展 `tests/ui/test_main_window.py`，验证识别结果标签使用专用高对比度样式。
- 运行定向测试，确认修改实现前测试按预期失败。

## Task 2：修复采集门槛与诊断提示

- 将 `configs/app.example.json` 的 `min_sharpness` 改为 40.0。
- 将本地忽略文件 `configs/app.json` 同步改为 40.0，便于用户立即复测。
- 修改 `face_recognition_app/core/quality.py`，在清晰度不足原因中显示一位小数的实际值和门槛。
- 运行配置和质量检查定向测试。

## Task 3：修复深色主题文字对比度

- 为登记向导的姿态、原因标签设置对象名。
- 为普通标签、姿态提示、拒绝原因与进度条增加显式高对比度 QSS。
- 为主界面识别结果和普通状态文字增加显式浅色样式。
- 保持警告、错误和禁用状态的现有专用颜色。
- 运行登记向导与主窗口离屏测试。

## Task 4：验证与交付

- 运行完整 pytest 测试套件。
- 对应用和测试执行 `compileall`。
- 同步并检查 CodeGraph。
- 执行 `git diff --check`。
- 更新 `task_plan.md`、`findings.md` 和 `progress.md`。
- 提交并推送修复，提供 ONNX 模式人工复测命令。

## 验收标准

- 普通室内画面清晰度约 58 时不再被 100 分门槛持续拒绝。
- 严重模糊画面仍会被 40 分门槛拒绝。
- 模糊提示显示类似“清晰度 23.5/40.0”的诊断信息。
- 截图中原为黑色的姿态提示、原因、0/15 和主界面结果均变为高对比度文字。
- 全部自动化测试与语法检查通过。
